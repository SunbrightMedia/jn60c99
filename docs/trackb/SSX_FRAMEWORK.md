# `sxgate` — a reusable sonic-equivalence gate framework

FINAL DESIGN. Synthesis of the two candidates: the winner's data-driven core
(pluggable adapter, frozen metrics, recorded teeth) with the loser's fully
specified manifest, 10-symbol C ABI and directory layout grafted on. Every
failure case that the judges found is closed below, and each fix is marked
**[FIX-n]** so a future session can check that it is present.

Label discipline: every claim in this document is READ (from the repo) or
INFERRED (design intent). Nothing here is PROVEN until the code runs.

---

## 0. What the framework is, and what it is not

`sxgate` answers three questions about a candidate engine, in this order:

1. **Was the code reached?** (coverage)
2. **Could an error in it be seen?** (canary / carriage)
3. **Is the output identical?** (null)

The third question alone is a lie detector that lies. The first two make the
third mean something. This order is the framework, and it is synth-agnostic.

`sxgate` does **not** choose your scenarios, write your mutations, or decide
your thresholds. It runs them, records them, and refuses to let you weaken them
quietly.

Two claims must never be mixed:

* **BIT-EXACT** — `src/` against the plugin binary. Proven by `make verify`.
  `sxgate` never touches it.
* **SONICALLY EQUIVALENT** — `native/` against `src/`. Proven by `sxgate`.

## 2. The engine contract (`sxgate_abi.h`)

Ten symbols. One output bus, interleaved float32, single thread.

```c
#define SXGATE_ABI 1

void*  sx_create   (double sample_rate, const int *opts, int nopts);
void   sx_destroy  (void *ctx);
int    sx_preset   (void *ctx, const unsigned char *blob, int len, int preset_id);
void   sx_note_on  (void *ctx, int note, int vel);
void   sx_note_off (void *ctx, int note);
int    sx_set_param  (void *ctx, int param_id, int value);    /* -1 if unsupported */
int    sx_set_param_f(void *ctx, int param_id, float value);  /* -1 if unsupported */
int    sx_render   (void *ctx, float *out, int nframes);      /* returns nframes */
const char *sx_abi (void);   /* "sxgate-1 <id> ch=<n> state=<bytes>" */
int    sx_selfid   (void);   /* 0 = reference build, 1 = candidate build.
                                build.py defines SXGATE_CAND=1 for the candidate.
                                Used by forkcheck to prove the two libraries
                                are not the same build.  [FIX-1] */
```

Obligations. `sxgate selftest` checks each one before any gate reports:

| # | Obligation | How checked |
|---|---|---|
| O1 | **Determinism** — same script twice in one process is byte-identical | 3 runs, must all match (closes JUNO open item F19) |
| O2 | **Isolation** — two live contexts interleaved == two sequential runs | catches globals |
| O3 | **No leaks** — 200 create/destroy cycles, RSS growth under a fixed slack | promotes defect 2 |
| O4 | **Exact frames** — `sx_render` returns `nframes` and fills `nframes*channels` | return value + length sentinel |
| O5 | **Marker reality** — every declared `[[sites]]` marker text is present in a file that the RESOLVED candidate source set actually compiles | greps the resolved set, not the tree |
| O6 | **Probe neutrality** — the perturb build with an EMPTY cell list reproduces the reference EXACTLY | tells "did nothing" from "never happened" |
| O7 | **Probe strength** — the perturb operator is multiplicative AND additive, and the additive term is `>= 1e-9 * typical_cell_magnitude` | promotes defects 1 and 3 |
| O8 | **ABI string** — `sx_abi()` matches the manifest id, channels, state_bytes | catches a stale .so |

A failed obligation exits **2** (vacuous), never 0 and never 1. A broken harness
can therefore never be read as a green gate.

### 3.2 `scenarios.toml`

```toml
fingerprint_fields = ["preset","rate","script","tag"]

[[scenario]]
tag    = "MONO retrigger"
preset = 15
rate   = 44100.0
why    = "patch 15 is the only factory MONO whose retrigger latch arms"
script = [ ["warmup",747], ["on",48,100], ["render",4000],
           ["on",52,100],  ["render",4000], ["off",52], ["render",2000],
           ["off",48],     ["render",8000] ]
```

Event language, the only thing gates interpret:
`["on",note,vel] | ["off",note] | ["param",id,value] | ["render",n] | ["warmup",n]`

Load-time INVARIANTS (each promotes a found defect to an assertion):

* **release-tail**: at least one `off` after the last `on`, and at least one
  `render` after the last `off`. (defect 4)
* **non-empty**: total rendered frames > 0.
* **fingerprint**: the hash over `fingerprint_fields` is stamped into
  `CARRIAGE.tsv`. A carriage map is valid only for the set that produced it.

### 3.3 `mutations.toml`

```toml
[[mutation]]
name    = "dcopitch"
class   = "global-pitch"     # global-pitch|subsystem-local|release-only|fx-kill|env-rate
file    = "src/juno_init.c"  # rewritten in the file ACTUALLY COMPILED (shadow-aware)
find    = "v32 = 1000568814;"
replace = "v32 = 1000568914;"
why     = "+100 ULP on the 220/44100 phase-increment scale, ~0.01 cent"
```

A `find` string that no longer occurs is a hard build-time error, never a skip.

### 3.4 `baseline.toml` — the recorded catch matrix

Per mutation, the exact SET of scenario tags that caught it, plus the bulk
count. `sxgate teeth` fails if a recorded set SHRINKS.

**[FIX-4] The baseline may not be machine-blessed on first use.** For the JUNO
it is TRANSCRIBED BY HAND from the measured numbers already in the repo, and the
migration passes only if the new code reproduces them. Thereafter:

* `--record` on a manifest that already has a baseline is **refused**.
* `--rebaseline --why "<text>"` is the only path. The text and the old numbers
  are appended to the file and to `EQUIVALENCE.tsv`, so a weakening shows up in
  every diff and in the audit trail.

## 4. Gates and CLI

```
sxgate selftest                  fixtures + ABI obligations O1..O8
sxgate forkcheck                 shadow reality (PRECONDITION for every gate)
sxgate null                      smoke: scenarios only (NEVER acceptance)
sxgate null --full               presets x scripts x rates
sxgate null --fuzz               seeded sequences with live param edits
sxgate null --all                ACCEPTANCE
sxgate teeth [--rebaseline --why T]
sxgate coverage --module M1a
sxgate observability --sweep | --cells 320,560 [--site N]
sxgate canary --module M1b [--max N]
sxgate accept --module M1b       runs the whole loop, appends one ledger row
sxgate cross --module M1b        null under qemu at the shipping opt level
```

Exit codes, uniform: **0** pass · **1** fail · **2** vacuous / precondition
unmet. Nothing else.

### 4.1 `forkcheck` — the shadow-reality precondition **[FIX-1, FIX-2]**

The judges' worst concrete failure was a self-comparison that nulls at EXACTLY 0
and looks perfect. `forkcheck` runs before every other gate and asserts:

1. `build.py` emits the RESOLVED source set for each side.
   `reference ∩ shadow = ∅` **and** `candidate ∩ shadow = shadow`.
   A shadow entry that resolves to nothing is an error, not a silent skip.
2. Both sets' file SHA256 lists are recorded and go into every ledger row.
3. `sx_selfid()` returns 0 from the reference library and 1 from the candidate.
4. **Shadow teeth** — plant a marker mutation in a shadow file only. The
   CANDIDATE output must change; the REFERENCE output must not. This test does
   not depend on the candidate being a verbatim passthrough, so it keeps working
   after module 1 is rewritten. That is the fix for the winner's self-disabling
   S1. **[FIX-5]**
5. While the candidate is still a verbatim fork, the passthrough null must be
   EXACTLY 0. Once it is not, the run is labelled `NO-PASSTHROUGH-PROOF` and
   step 4 carries the load.

### 4.2 `null` — the identity gate

Two metrics, both gating, both FROZEN (§5):

* global relative residual RMS, threshold `global_db`;
* worst `block_frames`-sample block residual against that block's own level,
  floored at `block_floor` of the global RMS, threshold `block_db`.

Rules:

* Unequal stream lengths score **+999 dB**. Never a small residual.
* A reference below `signal_floor_db` reports **INVALID** (exit 2), not PASS.
* If more than `vacuity_frac` of a bulk run is vacuous, the bulk gate FAILS.
* **[FIX-3]** `null` refuses to print PASS for a run tagged with a module whose
  latest canary result is below `min_observable`, or whose canary is missing or
  stale (fingerprint mismatch). It exits 2 with
  `BLIND GATE: module M2 observable 5/12 = 0.42 < min_observable 0.75`.
  The standing rule "NO MODULE MAY BE REWRITTEN BEHIND A BLIND GATE" becomes an
  exit code, not prose.

### 4.3 `coverage`

gcov line counts from the coverage build, one process per scenario so counters
do not accumulate. Reports any scenario that misses the module range and any
target line that no scenario reaches. **[FIX-7]** `accept` requires a coverage
run whose fingerprint matches the current scenario set; a stale one is refused.
Recorded assumption, printed every run: *coverage is measured on the host x86
`-O1` build and is a PROXY for the `-Os` Cortex-M7 build.* `sxgate cross`
partly compensates.

### 4.4 `observability` (carriage)

Perturbs a stored cell at a declared site and classifies CARRIED / NOT-CARRIED.
The claim is narrow and stays narrow: **it says whether the stored value is
carried, not whether a wrong answer would be noticed.** Consumers read locals,
and some saturate. Module admissibility is `canary`'s job.

Both probe profiles are always run (O7): CLASSIFY `(mul=1.001, add=1e-6)`,
CALIBRATE `(mul=1.00000012, add=0.0)`. A cell is NOT-CARRIED only if BOTH report
zero residual.

### 4.5 `canary` — module admissibility

Plants a 0.1 % error in each assignment of a module's line range, one build per
assignment, and reports how many scenarios catch each. Output is a fraction and
a blind-line list, written to the module's ledger row. Run it BEFORE the
rewrite.

### 4.6 `accept`

Runs forkcheck → selftest → coverage → canary → observability → teeth → null
`--all` (+ `cross` if configured), then appends ONE `EQUIVALENCE.tsv` row with
every column filled. A blank column is rejected; the only legal placeholders are
`SKIP:<reason>` and `NOT-RUN:<open-item>`. Rows are append-only.

## 5. Frozen metric layer

`metric.py` is copied verbatim from `tools/trackb/null_ab.py`
(`db`, `rel_residual`, `block_residual`, `judge`) and is then **frozen**. Pure
Python, pure `math`, unchanged summation order. numpy is banned: it changes
float summation order and would make every dB already recorded in
`CARRIAGE.tsv` and `EQUIVALENCE.tsv` incomparable. A change to this file
requires a new `schema` number and a full re-record.

Measured meaning of the thresholds, carried forward as documentation and
re-checked by `teeth`: a 2-ULP/sample error lands at −129 dB, so −90 dB ignores
up to roughly 200 ULP/sample. That is far under audibility and far over float
noise.

## 6. `fixtures/tinysynth.c` — the framework's own teeth

A ~200-line toy engine with KNOWN answers, so that coverage, observability and
canary have teeth for the first time. It must contain, by construction
**[FIX-8]**:

| feature | asserted result |
|---|---|
| an ordinary carried cell | CARRIED |
| a write-only cell with no reader | NOT-CARRIED |
| **a cell whose at-rest value is 0.0 but which is read later** | CARRIED — a multiplicative-only probe would call it NOT-CARRIED (defect 1) |
| **a consumer that clamps its input** | ×3 changes nothing, +1 changes everything (defect 5); canary must still mark the module observable through the additive probe |
| **a cell read after one multiply by ~1e6** | proves the additive term survives; a `1e-20` term must be REJECTED by O7 (defect 3) |
| a line no scenario reaches | coverage reports dead |
| a deliberately blind module (`min_observable` set high) | `null` exits 2 with BLIND GATE |
| a planted mutation | caught in the recorded scenario set |
| a clean control | EXACTLY 0.0 |
| a leaking variant behind `#ifdef` | O3 fails |

`sxgate selftest` runs all of this with no real synth attached. It is CI-safe
and is the regression net for the framework itself.

## 8. Porting a NEW synth — blind checklist

Work top to bottom. Do not skip. A step that cannot be completed is a stop, not
a note.

1. **Write the shim.** Implement the ten `sx_*` symbols over your engine's own
   entry points. Do not put DSP in the shim. `sx_render` must fill exactly
   `nframes*channels` and return `nframes`.
2. **Write `sxgate.toml`.** Fill `[project] [engine] [presets] [build]`. Put the
   preset blob's sha256 in. Use `reference = { mode = "recipe" }`. Set
   `shadow.rule = "manifest"` and create the OVERRIDES file, empty for now.
3. **Run `sxgate selftest`.** It must pass with the candidate as a verbatim
   copy of the reference. If O1–O8 fail, fix the ENGINE, not the framework.
4. **Run `sxgate forkcheck`.** Passthrough null must be EXACTLY 0, and the
   shadow-teeth test must show the candidate changing while the reference does
   not.
5. **Write `scenarios.toml`.** This is the real work and no framework can do it.
   Rules: every scenario ends with note-offs and a tail; every scenario states
   `why` in one sentence; cover each subsystem you intend to touch; include at
   least one scenario per voice-allocation mode.
6. **Write `mutations.toml`.** At minimum one mutation per class in the
   taxonomy: global-pitch, subsystem-local, release-only, fx-kill, env-rate.
   Plant them in the reference source; the framework redirects to the shadow
   file when one exists.
7. **Run `sxgate teeth --record`** ONCE, read every number, and only then commit
   `baseline.toml`. A mutation caught by 0 scenarios is a **gate hole**, not a
   pass — go back to step 5. After this commit, `[thresholds]` becomes usable.
8. **Materialise the state model.** Either commit a `CELLS.tsv`
   (`model="manifest"`) or, for a decompiled port with macro accessors, set
   `model="regex"`. There is no DWARF extractor; do not wait for one.
9. **Declare `[[sites]]`** and put the matching `SX_HOOK(n)` markers in the
   candidate source. O5 will refuse a marker in a file that is not compiled.
10. **Run `sxgate observability --sweep`.** Commit the carriage map with its
    scenario fingerprint.
11. **Declare `[[modules]]`** with line ranges and `min_observable`.
12. **Run `sxgate canary --module X` for EVERY module,** before writing any
    candidate code. Rank the modules by observability. This is your work order.
    A module below `min_observable` is blocked: add scenarios, then re-run.
13. **Cross the ranking with cost.** A well-gated module that costs 2 % of the
    budget is not where your overrun comes from. Gate quality decides what you
    MAY rewrite; profiling decides what you SHOULD.
14. **Rewrite one module.** Then, in order: `coverage` → `canary` →
    `observability` → `teeth` → `null --all` → `cross` → `accept`.
15. **`sxgate accept --module X`** writes the ledger row. If it refuses, the row
    would have been a lie. Do not hand-edit the ledger, ever.
16. **Never listen to decide.** No ear test, no user A/B. That is a capture and
    it is forbidden. The gates decide.

## 9. Known limits, stated plainly

* **Coverage is host-only.** gcov measures an x86 `-O1` build. It is a proxy for
  the target build. `sxgate cross` reduces but does not remove this.
* **Scenario and mutation authoring cannot be generalized.** The framework gives
  the taxonomy, the runner, the never-shrink rule and the feedback loop. It will
  never pick your patch or write your mutation. "Zero Python per synth" is a
  claim about code, not about thought.
* **`reference = { mode = "artifact" }`** re-introduces the flag asymmetry the
  recipe mode exists to prevent. It is legal, and every gate header prints
  `WEAKENED: artifact reference` when it is used.
* **The baseline is a policy problem.** `--rebaseline --why` makes weakening
  visible in a diff and in the ledger. A determined operator can still defeat
  it. There is no technical fix; the mitigation is that the reason is written
  down.
* **DWARF state extraction is declared and NOT implemented.** `config.py`
  rejects it, rather than pretending to generality.
* **One bus, interleaved float32, exact frame counts.** Multi-bus or
  block-quantized engines must hide that in the shim, and a nontrivial shim is
  untested code between the gate and the engine. Mitigation: the shim is C, it
  is compiled identically into both sides, and the passthrough null must be
  EXACTLY 0.
