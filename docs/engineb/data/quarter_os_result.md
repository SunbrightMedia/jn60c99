# ROW 4's DCO HALF IS CLOSED NEGATIVE — 1× oversampling cannot make the tone

Date 2026-08-06 (Opus 5), executing row 4 of `S3_PLAN_THAT_FITS.md`.

**THE SENTENCE FIRST: the 1× DCO does not reproduce the instrument's
harmonics, and no edge width fixes it.** Row 4's DCO half was 6,178 of the
7,658 instructions the plan depended on. It is dead. The plan's endpoint moves
from 1.02× to **1.48×**, and 6 voices with full FX at 44.1 kHz does not fit on
today's evidence.

## What was built

`EB_QUARTER_OS=1`: `EB_DCO_SUBSTEPS` 1, the increment scaled ×4 through the
engine's own `eb_dco_inc_scale`, and a decimator arm with **no FIR** — an
anti-imaging filter with one input per output is a delay. The biquad tail
stays byte for byte, because it is rate-dependent recall data and not part of
the anti-aliasing.

Measured with the alias gate that already existed,
`tools/engineb/o8_gate2.py`, extended with two columns for the 1× build.

## What the physics said first, and it was right

The port's edge is `clamp1(tri(x) · g · 256 · amp)` with `g = (1/256)/inc4`,
so `g·256 = 1/inc4` and the edge spans `inc4/amp` in phase — a **fixed
duration in time**, independent of how many sub-samples that duration is cut
into.

So oversampling does not change the edge's spectrum. It changes how accurately
the edge is **sampled**. At 4× the ramp is sampled four times and decimated.
At 1× it is sampled once, and where that one sample lands in the ramp is the
aliasing.

The measurement agreed: at 1× with the edge unchanged, the alias floor rises
**+2.3 dB at 3.5 kHz, +5.6 dB at 7 kHz, +2.7 dB at 10.6 kHz** against F5's
+1.0 dB bound.

## The edge-width sweep, and the trap it walked into

Widening the ramp toward one output sample is the first-order band-limited
step, and `g` is exactly that knob: dividing `g` by W widens the ramp by W.

It was **swept, not chosen**, because at 2× the same reasoning said "halve g"
and measurement said the opposite — 4.95 dB of in-band tilt. A knob whose sign
has already been wrong once gets swept.

| edge width | worst alias rise | worst harmonic error |
|---|---|---|
| ×1 | +5.6 dB | **13.6 dB** |
| ×4 | +3.8 dB | **56.2 dB** |
| ×6 | **+0.9 dB — passes** | **73.3 dB** |
| ×8 | −1.4 dB | worse still |

**Widening an edge is a low-pass.** It lowers the alias floor and the
harmonics together. At ×6 the alias bound passes and the instrument is gone.

**Reporting only the alias floor would have shown ×6 as a clean pass.** The
harmonic column was added for that reason, and it is the reason this rung is
closed rather than shipped.

## The finding, which is not about edges at all

**Even at ×1 — no widening, the port's own edge — the harmonics are 7.1 to
13.6 dB wrong.** The 2× build's worst harmonic error is 0.01 to 3.27 dB.

So the failure is not the edge and not the missing FIR. The DCO's harmonics
are generated by its **shaping nonlinearity**, which runs per sub-sample. A
waveform sampled at 44,100 Hz driven through that nonlinearity produces
different harmonics from the same waveform sampled at 176,400 Hz. F5 recorded
exactly this between 176.4 kHz and 88.2 kHz, where it was worth up to 3.3 dB
at bins 65–90 dB down. At 44.1 kHz it is 13.6 dB at bins that are audible.

**No filter placed after the nonlinearity recovers harmonics the nonlinearity
did not generate.** That is why there is no fix to try next, and why this is
recorded as closed rather than parked.

## What survives

* **Half-oversampling (2×) stands.** It is gated, it is worth 3,826
  instructions, and its worst harmonic error is 3.27 dB.
* **The VCF half of row 4 is untouched by this.** The ladder is a linear
  filter with no nonlinearity, so its rate reduction is an algebra problem —
  F5's `G' = 2G/(1−G²)` — not a harmonic-generation problem. It is still
  worth 690 instructions at 2× and it still needs the corrective one-pole that
  was never tried.
