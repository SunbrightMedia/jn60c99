# THE PLAN THAT FITS, VERSION 2 — 6 voices + full FX at 44.1 kHz

Date 2026-08-06 (Opus 5). Supersedes `S3_PLAN_THAT_FITS.md`, which was wrong
three times in one day. This one is built only from numbers measured on the
user's own board or by disassembling the target build.

**THE SENTENCE FIRST: it fits. 6 voices, full FX, 44.1 kHz, worst-case patch,
1.06× to 1.17× — and 0.91× on the patch a typical preset selects.** One item
carries it, and that item's design obstacle is named in §5 rather than left
for a later document to discover.

---

## 1. What was wrong with every earlier plan

Every earlier ladder priced the engine at its **worst dispatch arm** and never
asked what the instrument actually plays. Measured today over the factory
bank, using the port's own decoder:

| DELAY TYPE | instructions | patches |
|---|---|---|
| 0 | 320 | **23** |
| 1 | 1,015 | 15 |
| 2 / 3 | 1,279 | 9 |
| 5 | **1,979** | 4 |
| 4 | 1,225 | **0 — no factory patch selects it** |

The worst arm is used by **4 of 51 patches**. Charging 1,979 to every patch
overstates the FX chain by 1,659 instructions, and the FX chain's measured
cycles-per-instruction is 2.36 — so that is **3,915 cycles, more than a third
of the entire two-core budget**, charged to 47 patches that do not incur it.

Both columns are carried through this whole document. A budget must cover the
worst case; a plan should not be judged only by it.

## 3. The ladder

Starting point is today's engine with every gated lever on: the S3 fork,
shared LFO, DCO reciprocal, DCO edge short-circuits, the glide hoist, the
`vcf_res` table and half-oversampling. **12,861 voice instructions, 4,041 FX
instructions (worst arm) or 1,617 (cheapest arm).**

| step | worst patch | typical patch |
|---|---|---|
| today, all gated levers | 31,705 = **2.91×** | 25,984 = 2.39× |
| 1. FX rings to internal RAM | 27,421 = 2.52× | 24,270 = 2.23× |
| 2. block processing | 25,516 = 2.34× | 22,365 = 2.05× |
| 3. voice interleaving (c/i 1.15) | 19,637 = 1.80× | 16,850 = 1.55× |
| 4. VCF ladder 4× → 2× | 18,844 = 1.73× | 16,056 = 1.48× |
| 5. envelopes 1/8 + three divisions | 17,245 = 1.58× | 14,458 = 1.33× |
| 6. **WAVETABLE DCO** | **12,740 = 1.17×** | **9,952 = 0.91×** |
| 7. interleaving to c/i 1.0 | **11,508 = 1.06×** | 8,842 = 0.81× |

**Row 6 carries the plan.** It alone is worth 4,505 cycles. Every row before
it together reaches only 1.58×.

If 44.1 kHz still will not close, **32 kHz** — the rate Roland's own D-50 and
JV series ran at — gives a 15,000-cycle budget and the same ladder lands at
**0.85× worst, 0.66× typical** after row 6. That is a user decision of the
same class as the alias relaxation, not an engineering one.

## 4. Rows 1 to 5

**Row 1 — FX rings to internal RAM. MEASURED and possible**
(`data/ring_depth.md`). The nine rings allocate 6.16 MB and use **0.26 MB**;
the deepest read in the whole engine is 0.70 seconds. 266 KB fits the S3's
512 KB. This removes the PSRAM wait that makes the FX chain's c/i 2.36.

**Row 2 — block processing.** The 2,105-cycle intercept is per-sample call and
setup overhead attributable to neither chain. Rendering in blocks amortises
it. It changes no arithmetic.

**Row 3 — voice interleaving.** c/i 1.56 is not memory: moving voice state to
internal RAM measured 12,718 cycles against 12,720, and moving code to IRAM
measured 12,820. It is FPU result latency — each operation waiting for the one
before. Two voices are independent, so their operations fill each other's
delays. LTO already showed 5.8 % from the same effect.

**Row 4 — VCF ladder 4× → 2×.** F5's declined rung. The ladder is a **linear**
filter, so unlike the DCO its rate reduction is an algebra problem —
`G' = 2G/(1−G²)` — not a harmonic-generation one. It still needs the
corrective one-pole that was never tried.

**Row 5 — envelopes at 1/8 rate and the three remaining divisions.** Small and
well understood. `data/c2_result.md` forbids everything else in this category.

## 5. Row 6 — the wavetable DCO, and its real obstacle

The DCO is 3,006 instructions of the 12,861, and the decimator that exists
only to serve it is another 912. Replacing both with table reads is worth
**3,918 instructions**.

### Why the earlier attempt failed and this is different

`data/quarter_os_result.md` closed 1× oversampling: the DCO's harmonics are
generated by a **shaping nonlinearity** that runs per sub-sample, so a
coarsely-sampled waveform through that nonlinearity produces harmonics that
are 7 to 13.6 dB wrong, and no filter afterwards recovers them.

A wavetable does not run the nonlinearity at the output rate. It **stores the
result** of running it properly, once, at recall time, and reads it back
band-limited. That is the same distinction that made the `vcf_res` table work
where C2's decimation of the identical span failed at −39.3 dB.

### The obstacle, stated

The saw and sub arms are functions of phase alone and tabulate directly. **The
pulse arm depends on the pulse width, which the LFO modulates.** A table
rebuilt whenever pw moves is not a saving.

**The route worth trying first** is the band-limited-step identity: a pulse of
width w is `saw(p) − saw(p + w)`. One mip-mapped table then serves the saw
arm, the pulse arm at any width, and the sub arm an octave down — and PWM
becomes a **phase offset**, never a rebuild.

**What that costs, honestly:** the identity gives an *ideal* band-limited
pulse, not Roland's shaped one. It is a fork relaxation and must be gated like
every other — F5's gate 1 and gate 2 already exist, and after
`quarter_os_result.md` the **harmonic-level column is mandatory**, because the
alias floor alone would have passed a build with 73 dB of harmonic error.

### Measured on the way

Pulse width per voice over all 36 scenarios, 17,199,360 calls: it moves on
**52 %** of samples, span [−0.015, 0.939].

The first version of that probe compared **consecutive calls, which are
different voices**, and reported 100 % motion with a worst step of 0.86. That
number is CONDITION scatter between voices, not motion in time. It would have
killed this lever outright. Recorded because the same mistake is available to
anyone who repeats the measurement.

## 6. Order of work

1. **Row 1**, then **row 2**, then **row 3** — all three need the board, none
   changes any arithmetic, and row 3's result gives the real c/i that rows 4
   to 7 all depend on.
2. **Row 6** — the wavetable DCO. Host-gateable. Build the saw table and the
   band-limited-step pulse first, and gate with the alias probe **and** the
   harmonic column.
3. **Rows 4 and 5** — trim, once row 6 has decided whether they are needed.

## 7. What is measured and what is not

| | |
|---|---|
| MEASURED | the budget; c/i 1.56 / 2.36; the intercept; every instruction count; the ring depths; the arm distribution; the pw motion |
| GATED | fork, shared LFO, recip, edge short-circuits, glide hoist, `vcf_res` table, half-oversampling |
| ESTIMATE | every row of §3 |
| UNPROVEN AND LOAD-BEARING | row 6 |

**This plan fits on arithmetic built from measurements. Row 6 is not built.**
If row 6 fails the way row 4's DCO half failed, the ladder stops at 1.58× at
44.1 kHz and 1.15× at 32 kHz, and the answer is 32 kHz or five voices.

That sentence is here because the last three plans each promised a fit and
each lost it to one unbuilt row. This one names which row that is before any
work starts.
